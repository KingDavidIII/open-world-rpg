# v1.0 Core Gameplay and Performance Overhaul

## Status

The v1.0 release remains blocked until real playtesting confirms stable frame pacing and a convincing block-survival loop. Automated correctness is necessary, but it is not a substitute for responsive gameplay.

## Performance architecture

The voxel runtime now separates world streaming into bounded stages:

1. Terrain is generated incrementally instead of generating an entire new render area in one frame.
2. CPU mesh construction runs on a dedicated worker thread from immutable snapshots.
3. GPU buffers are created and replaced only on the main OpenGL thread.
4. Existing chunk meshes remain visible while edited replacements are built.
5. Terrain required by collision and natural features is prefetched as a complete neighbourhood.
6. Natural-feature collision never triggers an unexpected synchronous terrain generation.
7. The F3 diagnostics report rolling average FPS, 1% low FPS, p95 frame time, worst frame time, stall counts, and streaming backlog.

The rolling frame window contains ten seconds at 60 FPS. A stall is a frame of at least 100 ms. A severe stall is a frame of at least 250 ms.

## Core survival feel

The first survival objective now uses an actual block-built starter tree rather than loose logs placed on the ground. Trees use distinct log-top, log-side, and leaf textures. Wood and leaf blocks participate in targeting, collision, mining, save data, and mesh invalidation.

Movement now includes controlled acceleration and braking, sprint field-of-view feedback, and restrained grounded camera bob. Input is stopped immediately whenever gameplay loses mouse capture so menus do not inherit movement momentum.

## Release playtest gate

A release candidate must complete a continuous traversal test across at least six chunk boundaries and satisfy all of the following:

- no repeated collapse to 4–6 FPS;
- rolling 1% low of at least 30 FPS after initial loading;
- no repeated severe stalls of 250 ms or longer;
- no progressive slowdown during a 20-minute session;
- starter tree is obvious from spawn and all four trunk blocks can be mined;
- logs are collected, crafted into planks and sticks, and used to progress to stone;
- block edits remain visible while replacement meshes are generated;
- save, continue, backup recovery, death, and respawn remain functional.

A build that fails any one of these checks is not eligible for v1.0 tagging.
