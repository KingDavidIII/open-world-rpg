# v1.0 Release Candidate Audit and Stabilisation

## Purpose

This sprint converts the v0.9.0 playable prototype into a controlled v1.0 release
candidate. The package version intentionally remains `0.9.0` until the final release
preparation commit.

The release-candidate scope is defect correction, resilience, observability,
playtesting support, packaging preparation, and repeatable validation. It does not
add enemies, quests, NPCs, multiplayer, advanced biomes, or a larger crafting tree.

## Audit findings and resolutions

### The primary command did not launch the game

`python -m open_world_rpg` and `open-world-rpg` previously executed only the
rendering-free lifecycle check. The primary launcher now starts the playable voxel
survival release. The former behaviour remains available explicitly through
`--runtime-check`.

The launcher also exposes `--version`, configurable data and save paths, display
size, target frame rate, render distance, world seed, direct play, autosave, startup
load, and bounded smoke-test frames.

### Voxel launch failures were not reliably diagnosable

The playable launcher now configures the existing JSON runtime logger before
creating the renderer. Unhandled launch or runtime failures produce an atomic JSON
crash report under `crash-reports/` and print its path when a console is available.
Crash-report failures are isolated so they cannot mask the original game failure.

### Save replacement had no retained recovery point

Every replacement save now rotates the previous primary file into a single
`*.backup.json` recovery file. The new primary is still written through a flushed,
atomically replaced temporary file.

Load now attempts automatic recovery when the primary file is missing, unreadable,
or structurally corrupt. A valid backup is restored to the primary path without
consuming the backup. Unsupported future save-schema versions are not silently
replaced with older data.

The in-game feedback message explicitly reports when a world was recovered from a
backup.

### Custom save paths were not canonical on case-sensitive filesystems

Save-slot names are normalised by the storage boundary. The voxel application now
stores and tests the canonical path returned by that boundary, avoiding a mismatch
between existence checks and actual writes when a requested filename contains
uppercase characters.

### Renderer configuration accepted weakly validated values

Window dimensions, target frame rate, render distance, world seed, hidden-window
state, and terrain configuration now have explicit release-safe validation before
SDL or OpenGL initialisation begins.

### Release validation and Windows packaging were manual

`tools/validate_release.ps1` provides the definitive repeatable release gate:

- editable installation
- Ruff lint and format verification
- strict mypy
- complete test suite
- zero-skipped-test enforcement
- zero missing statements and branches
- both graphical import orders
- dependency validation
- module and installed launcher version checks
- rendering-free lifecycle acceptance
- primary and dedicated voxel smoke tests
- terrain smoke tests
- whitespace verification and proof that validation does not mutate the candidate diff

`tools/build_windows_release.ps1` validates the repository, builds a one-file
Windows executable with PyInstaller, and creates a versioned ZIP containing the
executable, licence, README, and launch notes.

A Windows GitHub Actions matrix now validates Python 3.11 and 3.12, builds package
distributions, and verifies the produced wheel.

## Runtime data layout

With the default launcher configuration, the selected data directory contains:

```text
<data-dir>/
|-- saves/
|   |-- voxel.json
|   `-- voxel.backup.json
|-- logs/
|   `-- open-world-rpg.log
`-- crash-reports/
    `-- open-world-rpg-crash-<timestamp>-<process>.json
```

The default data directory is the current working directory for Python launches and
the executable directory for packaged Windows builds. Packaged releases should be
launched from a writable folder.

## Release-candidate command surface

```powershell
python -m open_world_rpg --version
python -m open_world_rpg --runtime-check
python -m open_world_rpg
python -m open_world_rpg --data-dir .\runtime-data
python -m open_world_rpg --load --autosave
python -m open_world_rpg --width 1600 --height 900 --target-fps 60
python -m open_world_rpg --render-distance 2 --world-seed 42
python -m open_world_rpg --smoke-test --smoke-frames 60
```

## Acceptance boundary

The sprint is complete only after the Windows Python 3.11.8 environment confirms:

- every automated test passes
- zero tests are skipped
- statement and branch coverage remain exactly 100%
- both graphical test orders pass
- both primary launch forms report version `0.9.0`
- primary, voxel, and terrain smoke tests pass
- manual playtest checklist is completed without a release-blocking defect
- validation leaves the candidate working-tree state unchanged
