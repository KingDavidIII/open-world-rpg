# v0.9.0 Sprint 2 — Inventory, Crafting, and Game Flow

## Objective

Sprint 2 turns the v0.8.0 inventory and survival foundations into visible,
player-operated systems. The interactive voxel entry point now owns a complete
screen-state flow instead of relying on developer-only function keys and direct
world entry.

The released package version remains `0.8.0` until the complete v0.9.0 release
cycle is prepared.

## Delivered systems

### Inventory interaction

- Full 27-slot inventory screen with a nine-slot hotbar and 18-slot backpack
- Keyboard and mouse slot selection
- Atomic move, merge, split, swap, and deterministic quick-move policies
- Hotbar and backpack synchronisation through one authoritative inventory
- Tool durability displayed as current and maximum values
- Resource-stack rendering for logs, planks, and sticks
- Gameplay input suspended while the inventory overlay is open

### Crafting

- Stable renderer-independent recipe catalogue
- Atomic crafting that never consumes ingredients when output cannot fit
- Wood-log to plank conversion
- Plank to stick conversion
- Wooden pickaxe and wooden shovel recipes
- Stone pickaxe and stone shovel recipes
- Craftability feedback and explicit failure outcomes

### Game flow

- Main menu with New World, Continue, and Quit
- Continue availability based on an existing configured save
- Pause menu with Resume, Save, Save & Quit, and Quit Without Saving
- Save-and-quit behaviour that exits only after a successful save
- Inventory and crafting screen opened with `E` or `Tab`
- Death screen with explicit Respawn and Main Menu actions
- Interactive entry point defaults to `saves/voxel.json`
- `--direct-play` remains available for development and diagnostics
- Smoke tests bypass the menu and remain bounded and headless

## Architecture

- `gameplay/crafting.py` owns immutable recipe contracts and atomic crafting.
- `gameplay/inventory.py` owns slot transfers and quick-move transactions.
- `ui/voxel/game_flow.py` owns renderer-independent screen transitions.
- `ui/voxel/inventory_ui.py` owns inventory/crafting selection policy.
- `ui/voxel/application.py` adapts Pygame events and HUD rendering to those
  policies without duplicating domain rules.

## Controls

- `E` or `Tab`: open or close inventory and crafting
- Arrow keys: move inventory or menu selection
- `Enter`: select/move an inventory slot or activate a menu action
- `Q`: quick-move the selected inventory slot
- `[` / `]` or `Page Up` / `Page Down`: select a recipe
- `C`: craft the selected recipe
- `Escape`: pause during play; close inventory; resume from pause
- Mouse: select slots, recipes, and menu options

## Acceptance criteria

- Existing v0.8.0 saves remain readable.
- New resource identities serialize through the existing schema-v1 inventory
  payload without a schema migration.
- Crafting is atomic and increments the authoritative inventory revision once.
- Menu and inventory overlays suspend gameplay input.
- Direct-play and graphical smoke-test workflows remain available.
- Ruff, formatting, mypy, dependency, graphical-order, CLI, and complete
  coverage gates remain mandatory before commit.
